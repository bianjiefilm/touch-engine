# HUI-1671 R3 发布奖励规则内核 Implementation Plan

> **For agentic workers:** 本计划只覆盖规则内核。不要做 HTTP、页面或发券。

**Goal:** 用可重复的事件判定覆盖官方发布证据、待核实、人工凭据、幂等、跨租户、撤销和规则版本，且不产生渠道回执或 Billing 动作。

**Architecture:** 新包 `server/internal/rewardrule` 自持内存账。`publishreward`、HTTP 和 Web 保持原样，互不引用。

**Tech Stack:** Go 标准库。`GOWORK=off go test ./internal/rewardrule/ -count=1`。

**Spec:** `docs/superpowers/specs/HUI-1671-r3.md`

## Global Constraints

- 事件种类只收 `click`、`export`、`submit_publish`、`official_publish_success`、`manual_credential`。
- `official_publish` 只被 `official_publish_success` 满足。点击、导出、提交发布不发放，也不写「已发布」。
- 人工凭据是 `pending_review`，不发放。未确认发布的状态文本是「待核实」。
- 幂等键是租户、活动、规则版本、主体、事实 ID。撤销后的重放不发放。换版本不追溯旧事实。
- 别的租户即使事实 ID 相同也拒绝。
- 券面额是营销金额。不调 Billing，不发券，不批量发布。
- fixture 不是渠道回执。真实平台发布在本包内不可核验时保持不满足。
- 不改 `server/internal/publishreward`、`httpapi`、`web`、`extrajump`、`cmd`、`go.mod`、`go.sum`。
- 不引入 shadcn。不改访客页。不合并，不 force-push。

## 不做

- 不挂公开或商家路由。商家配置界面是后续切片。
- 不新增迁移，不双写旧账本。
- 不跑浏览器。本切片没有页面。
