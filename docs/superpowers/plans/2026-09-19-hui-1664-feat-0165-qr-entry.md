# 计划:HUI-1664 FEAT-0165 二维码兜底入口(touch-engine)

- 日期:2026-09-19;票:HUI-1664(P0);分支 `hui-1664-feat-0165-qr-entry`(基于 main=324cd73)
- brainstorm:指挥者已代答(QR 服务端 PNG=skip2/go-qrcode;owner 下载端点;size 白名单 128/256/512;next 参数严格白名单;参数卫生忽略未知参数;五态+网络失败/入口不支持兜底;留资路径复用 T1;不做 NFC 写入/浏览器矩阵/发布奖励授权)。
- 红线:QR 与 NFC 共用 T0 活动解析与五态,**不建第二套活动/登录/素材模型**;QR 载荷=纯短码 canonical URL(无凭证/租户 ID/客户信息);URL 跳转限受控目标;不从二维码/URL 参数派生任何后台权限。

## 1. 服务端 QR 包 `internal/qrentry`(纯逻辑,先行测试)

- `PublicEntryURL(base, code)`:base 去尾斜杠,必须是 http(s) 且无 query/fragment/userinfo;code 过 `campaign.ValidShortcode`;产物恒为 `base + "/c/" + code`(断言不含 `?`/凭证/租户/客户信息)。
- `Sizes = {128,256,512}` 白名单;`PNG(url, size)` 用 `github.com/skip2/go-qrcode`(Highest 纠错)出 PNG 字节;非白名单 size 显式报错。
- 回读断言(测试):PNG → 解码(gozxing,测试专用依赖)内容 == canonical URL;载荷卫生矩阵(无 query、无 token 形态值)。

## 2. 配置

`PUBLIC_BASE_URL`(env `PUBLIC_BASE_URL`,H5 对外基地址)。**决策**:不进全局 `Gate()`(避免把游客面/全部鉴权面与 QR 可用性耦合、保持既有测试语义),QR 端点独立 fail-closed:缺配置 → 503 `qr_not_configured`。

## 3. 鉴权

新增 `authz.ActionExportQR`(owner-only,staff → `forbidden`);cross-tenant/disabled 语义复用现有矩阵。HTTP:`GET /api/v1/campaigns/{id}/links/{linkId}/qrcode?size=256`(默认 256;`format=json` 返回 `{url,code,size}` 供面板显示与载荷断言,默认 png 下载,`Content-Disposition: attachment`)。QR 挂在 link 级(一个活动可有多码),复用 T0 五态解析,**零新增活动/登录/素材模型**。

## 4. 参数卫生与重定向守卫

- Go:公共面不读任何 query(现状即如此,补测试钉死):`?token=/tenant=/admin=1/next=//evil` 与干净请求字节级一致;请求日志只打 path(`r.URL.Path`),断言伪造参数值不入日志;admin 面 query `?role=owner` 不改变 authz。
- Web 纯函数 `src/lib/safe-redirect.ts`:`sanitizeInSitePath(raw)` 仅放行 `^/[a-z0-9/_-]*$`(单次 decode 后再验),拒绝 `//`、绝对 URL、`%2F`、反斜杠、多次编码、`javascript:`、空白;`next/redirect/return` 三键收集,非法一律 null(默认落地本活动页),合法仅用于站内返回锚(不做 router.push/window.location)。
- Web 纯函数 `src/lib/public-state.ts`:五态文案 + `network_error`(网络失败,重试动作)+ `entry_unsupported`(`entry` 参数非 {qr,nfc,web} 白名单 → 提示改用商家最新二维码/碰一碰标签);`failureState()` 把 fetch 抛错/BFF 503 归一为 network_error。`/c/[code]` 接线:重试按钮重跑加载,各态给可恢复动作文案。

## 5. 商家后台「二维码」面板(`/admin`)

活动表每行加「二维码」展开:列出该活动链接 canonical URL + size 选择(128/256/512)+ 下载 PNG(blob→a[download]);staff 收到 403 文案。无任何新权限模型。

## 6. TDD 顺序

qrentry 测试(URL 构造/载荷卫生/size 白名单/PNG 魔数+解码回读)→ authz 矩阵扩展 → config 注入 → httpapi QR 端点(owner/staff/guest/跨租户/size/缺配置/JSON 载荷)→ 参数卫生用例 → web safe-redirect+public-state vitest 矩阵 → BFF PNG 二进制透传 vitest → `/c/[code]` 与 `/admin` 接线 → 门禁。
