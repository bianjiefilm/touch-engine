## 目标

给定一条版本化规则和一条参与事件，内核做出唯一决定：这条规则是否被这条事件满足、是否记下一次工程发放、用户可见文案是什么。重复投递、别的租户、撤销之后的重放、以及换了规则版本的旧事实，都不得再发放。

券面额只是规则上的营销金额。本包不调用 Billing，不给任何人发券，也不做批量发布。

## 已在 main、本轮不改

以下代码已读，不改，也不把本轮说成对它们的重写：

- `server/internal/publishreward`：仍只消费 HUI-1670 的发布事实，渠道不能证明发布时不发放。
- `server/internal/db/migrations/0011_publish_reward.sql` 与 `server/internal/store/store_publish_reward.go`：账本仍强制未发券、未扣费。
- `server/internal/httpapi/handlers_publish_reward.go` 与 `web/src/lib/publish-reward.ts`：访客文案仍是待核实，手动证明仍不是平台确认。

本轮新包是 `server/internal/rewardrule`。它不引用上述包，也不被它们引用。

## 事件与证据

事件种类只有：`click`、`export`、`submit_publish`、`official_publish_success`、`manual_credential`。其它种类拒绝，不记发放。把「已发布」当作事件种类同样拒绝。

`evidence_level = official_publish` 的规则，只可能被 `official_publish_success` 满足。

- `click`、`export`：不发放。文案不是「已发布」。这不是一次未确认的发布，状态文本留空。
- `submit_publish`：不发放。不得标成「已发布」。这是未确认发布，状态文本是「待核实」。
- `manual_credential`：状态为 `pending_review`，不发放。状态文本是「待核实」。它不会变成平台确认。
- `official_publish_success` 且调用方声明这是渠道回执：本包不能核验真实平台发布，事件保持不满足，状态文本是「待核实」，不发放，不标「已发布」。
- `official_publish_success` 且明确标成 fixture：工程规则算匹配，可记下一次发放，用于验证幂等。fixture 不是渠道回执，`channel_receipt` 与 `platform_success` 都为假，文案不是「已发布」。生产发放仍是 `NOT_AUTHORIZED`。

`click` 或 `export` 即使带着 fixture 标记，也不满足 `official_publish`。fixture 不能把一种事件改写成另一种。

## 幂等、租户、撤销、版本

幂等键是：租户、活动、规则版本、主体、事实 ID。同一键再投递一次，不第二次发放；后一次若改了事件种类，仍沿用第一次的决定，不能把点击改记成官方发布成功。

事实 ID 第一次被记下时绑定该租户、活动和主体。别的租户再拿同一个事实 ID，拒绝，即使键里的事实 ID 相同。别的活动或别的主体复用该事实 ID，同样拒绝。不匹配的调用不写入新发放。

撤销只作用于已经存在的那条记录。撤销后，原事件再投递仍不发放。撤销本身不发券。尚未存在的键不能靠撤销造出一条发放。

更换规则版本必须带非空告知，版本号加一，证据等级仍是 `official_publish`。版本函数不重放旧账。旧事实拿到新版本上再投递，也不补发：以前没发放的仍然不发，以前已有的工程匹配也不再加一次。新的事实 ID 才按新版本重新判定。

## 券面额与停止线

`coupon_face_value` 是营销面额，币种只是标签。把它记入营销面额账户时，现金、public-ai 余额和顾客扣款都是 0，发券数和 Billing 调用数也是 0。记入 `ai_cash`、`public_ai_balance` 或 `customer_charge` 直接拒绝，并且不产生记账。

批量发布入口一律拒绝，不按主体列表发放。社媒密钥、令牌或凭据材料拒绝处理，决定和错误文本都不回显这段材料。

本包没有页面，所以浏览器是 `NOT_RUN`。没有外部服务调用，服务是 `NOT_VERIFIED`。没有 Billing 调用，计费是 `NOT_VERIFIED`。没有真人验收，Human 是 `UNKNOWN`。生产发放是 `NOT_AUTHORIZED`。

## 不做

不挂路由，不改商家 UI，不改访客页，不改 `publishreward` 的库表。不宣称渠道已经回执，不用 fixture 充当真实发布成功。不把券面额写成 AI 现金或顾客扣款。不合并，不 force-push。
