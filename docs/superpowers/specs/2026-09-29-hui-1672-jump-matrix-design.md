总指挥已经裁决设计问题和收尾方式。本文记录那个裁决，不再另问。

## 目标

已登记的店内目标、活动目标和授权回跳，访客点击后打开保存下来的那个地址。未登记的任意外部 URL 必须拒绝，不能靠查询参数或点击请求体把人送走。

三种证据分开记：网页可达、唤起客户端、平台动作成功。本机没有手机，原生唤起一律是 `unverified`。网页打开不是加企微、关注或点评成功。点击保持 `unknown`。

覆盖目标失效、未授权、撤销、返回和跨品牌。不自动关注、加群或付费。缺的能力在界面上禁用，或写明原因。

## 已合入、本轮不改

- 五个附加动作仍是 `wifi`、`navigate`、`review`、`wecom`、`follow`。未配置或非正式地址不出现可点按钮，拒绝的地址不回显。
- `https://shop.example.com/wifi` 这种商家已保存的公网 https 仍算正式地址。本轮不把 PR #19 收成域名白名单。
- 点击行仍然只能是 `recorded_as=click`、`success=0`、`platform_result=unknown`。不写留资、CRM、发奖或发布成功。
- 加企微和进社群的访客按钮仍走 HUI-1673 私域入口。活动跳转列表继续不重复展示 `wecom`。
- 查询参数 `next` / `redirect` / `return` 仍只允许站内相对路径。非法参数继续丢掉。
- 商家配置页和访客页沿用现有内联样式。不引入 shadcn/ui。
- 不改 leads-engine。不自动关注、加群或扣费。

## 做法

店内目标是 `wifi`、`navigate`、`review`。活动目标是 `follow` 和既有的 `wecom` 配置。授权回跳是单独一行，不是第六个随便的外链种类。

店内和活动目标沿用现有正式地址规则。在此之上：

- `revoked=true` 的目标关闭，原因 `revoked`，不带回地址。
- `expires_at` 早于或等于现在、或写了但解析不了，关闭，原因 `expired`，不带回地址。
- 点击请求体里的 `href` 忽略。响应里的 `href` 只可能是已保存且仍展示的地址。
- 活动已经结束、暂停、未开始或不存在时，公共跳转接口维持 404，不记点击。

授权回跳只接受两类地址：站内相对路径（`^/[A-Za-z0-9/_-]*$`，且不区分大小写地拒绝 `/admin` 和 `/api`），或主机名等于 `PUBLIC_BASE_URL` 或该活动已发布品牌主机的 https（无用户信息、无查询、无片段）。公开短码是大写的，所以回跳路径要能写下 `/c/` 加短码。其它外部 URL 保存时返回 400 `unregistered_url`，并且不改掉已经保存的跳转。未启用、撤销、过期的回跳不展示地址。

品牌开关打开时，公共跳转和回跳走与公共页相同的品牌裁决。`domain_mismatch` 和 `unknown_brand` 是 `cross_brand`。其它非 `available` 的品牌或租户状态是 `unauthorized`。这两种都不回显地址，也不记点击。品牌开关关闭时，行为与现在相同。

每条展示中的动作和每次点击都带：

- `evidence.web`：展示中为 `configured`，关闭为 `closed`。这只表示有没有可打开的网页地址。
- `evidence.client_launch`：固定 `unverified`。
- `evidence.platform_action`：固定 `unknown`。

支持矩阵同时写明 `auto_follow`、`auto_join`、`auto_pay` 都是 false。原生能力的原因里包含「原生唤起未验证」。

访客页在已有正式按钮之外，禁用或写明：连 WiFi、打开地图或点评客户端、自动关注、自动加群、付费。失效、撤销、未授权、跨品牌只显示原因，不显示地址。未配置和非正式地址继续不出现按钮。授权回跳先记一次未知点击，再打开服务端确认的同一个地址。

商家后台用现有样式增加跳转配置。只有 `org_owner` 能保存。其它角色看到「未授权，不能配置跳转」，控件禁用。加企微不在这张表里重复登记。BFF 补上 PUT 转发，否则后台无法保存。

要看到：已登记的店内或活动按钮打开的是保存的地址；页面写明网页可达、原生唤起未验证、平台动作未知；失效和撤销是禁用原因；授权回跳走到登记地址；未登记外部地址不能保存；结束的活动打不开跳转。
