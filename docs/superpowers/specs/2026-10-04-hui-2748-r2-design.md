## 目标

HUI-2748 的票面愿景是：商家在 touch 录一次门店与活动参数，Motion 侧用一个模板安全地派生多门店素材，全程不重复录入、不烧高价模型调用、顾客端不执行未审查代码。

真实 Motion 消费上游在本轮开工时不可用（见下节）。所以 r2 只做本域真实可行的消费者切片：把本仓已经记录的商家参数（HUI-2748 r1，PR #32/#33）扩展成完整的 Handoff Brief 输入（新增投放渠道与画幅比例），并把它投影成一个只读端点，供 Motion 侧上游就绪后消费。凡依赖 Motion Studio 的验收项保持未满足，逐项记录在验收矩阵里，不用桩关闭真实验收。

## 上游结论（已核实，2026-10-04）

真实 Motion 消费上游不可用，三条路径都不通：

1. **无合规导入路径。** HUI-2737 已合并 public-ai@d01ec88，Motion 共享契约实现在 `public-ai/internal/motionref`。Go 的 `internal` 可见性规则使业务仓（touch-engine）无法导入另一 module 的 internal 包。
2. **无 sdk 导出。** `public-ai/sdk/go` 最新 tag `v0.1.3`，全目录（含 platformconsumer）grep `motion` 零命中；origin/main 上也没有 motion 导出，且无导出时间表。
3. **HUI-2732 / HUI-2733 无开工痕迹。** public-ai 全分支历史 grep 无这两个票号的提交。

因此：票验收中依赖 Motion Studio 的项保持未满足；不复制 Motion Studio 编辑器；不新起 Motion 或矩阵服务；不得用桩关闭真实验收。

## 裁决 1：信任边界——web 不再照画服务端状态字符串

新建 `web/src/lib/store-motion-status.ts`，导出纯函数：

```ts
export function presentDeclaration(raw: string | undefined): { tone: "pending" | "unknown"; copy: string }
```

- `raw === "还没生成成片"` → `{ tone: "pending", copy: "还没生成成片" }`
- 空 / `undefined` → `{ tone: "unknown", copy: "状态未知（服务端还没给出声明）" }`
- 其他任何值（包括伪造的「已生成」「done」等）→ `{ tone: "unknown", copy: "状态未知（出现未识别状态）" }`

`store-motion-note.tsx` 改为消费此函数渲染状态行：`pending` 用既有 `tk-unknown` 语汇、`data-state="pending"`，不显示成功绿；`unknown` 用 `tk-unknown`、`data-state="unknown"`。任何状态都不渲染成成功色。vitest 真执行该函数（非源码断言），含「伪造状态字符串 → unknown」用例。

## 裁决 2：迁移 0019——channels / aspect_ratios

`server/internal/db/migrations/0019_store_motion_channels.sql`（additive，不动 0018 的任何 CHECK，不去动两个 0013）：

```sql
ALTER TABLE store_motion_requests ADD COLUMN channels TEXT NOT NULL DEFAULT '';
ALTER TABLE store_motion_requests ADD COLUMN aspect_ratios TEXT NOT NULL DEFAULT '';
```

注释写明：这是商家声明的投放渠道与画幅比例，属于 Handoff Brief 输入，不是 Motion 状态。

`storemotion.Params` 追加 `Channels`、`AspectRatios` 两个 `string` 字段（放在 CTA 之后；JSON 可省略，省略=空串；响应始终输出这两个键）。约束：

- 长度上限：`channels` ≤ 120 字节，`aspect_ratios` ≤ 40 字节。
- 格式约定：逗号分隔的小写 token，白名单正则 `^$|^(?:[a-z0-9_:/-]+)(?:,[a-z0-9_:/-]+)*$`（逗号只是分隔符，token 内不允许）；空串合法。违规 → 新错误 `ErrFormat`，handler 映射为 `400 invalid_field`。
- 复用既有隐私管道：两个字段先进 `strings.TrimSpace`，再过 `private()`（含手机号/邮箱/身份证/二维码载荷即 `ErrPrivacy`）。
- 六个旧字段的校验管道不变；`Request` 结构体与 `DisallowUnknownFields` 行为保持，六字段旧客户端不受影响（新字段缺省即空串）。
- `SaveStoreMotion` 幂等比较（`sameMotionParams` 结构体相等）自动覆盖到八字段：参数相同不新增版本的语义扩展到八字段，并有测试钉死（改 channels 必须出新版本，八字段全同必须 200 幂等）。
- `SaveStoreMotion` 的 INSERT 与 `LatestStoreMotion` 的 SELECT/scan 增加两列（旧行读回 `DEFAULT ''`）。

既有测试必须仍绿；其中 `TestPriceStaysAString` 硬断言 `NumField()==6`，本轮把它更新为八字段断言（字段序 `StoreName,ActivityTime,Price,Address,OfferCopy,CTA,Channels,AspectRatios`，仍全 string、仍禁结算字段名）——这是唯一允许改动的既有断言，原因写进任务。其余既有测试零改动必须通过。

新增用例：channels/ratios 合法写入回读、非法字符 400 `invalid_field`、超长 400 `invalid_field`、含手机号的 channels 400 `privacy_refused`、省略字段默认空串、幂等含新字段（八字段同→200 同版本；仅 channels 变→201 新版本）。

## 裁决 3：Motion Handoff Brief 只读投影端点

新增 `GET /api/v1/campaigns/{id}/motion-handoff`，挂在 `requireSession` 下，handler 内走 `campaignScoped(c, id, authz.ActionReadRecord, w)`（与 store-motion GET 同权限级别），不新增 feature 开关门。纯投影：不落库、不建表、不调 probe、不写任何 行。

活动未绑门店 → `400 store_required`（与 store-motion PUT 同语义）。

响应结构（JSON 字段名逐字如下）：

```json
{
  "version": "touch-motion-handoff/v1alpha1",
  "origin_context_ref": "touch:tenant/{t}/store/{s}/activity/{a}",
  "generated_at": "<RFC3339 UTC>",
  "campaign": { "id": "", "title": "", "public_content": "", "status": "", "starts_at": "", "ends_at": "" },
  "store": { "id": "", "name": "", "address": "", "status": "" },
  "brand": {
    "brand_id": "",
    "context_available": false,
    "context_unavailable_reason": "",
    "brand_config_version": 0,
    "published_brand_id": "",
    "published_host": ""
  },
  "offer": { "offer_copy": "", "price": "" },
  "cta": "",
  "channels": [],
  "aspect_ratios": [],
  "landing": { "short_code": "", "extra_jump_kinds": [], "authorized_return": { "href": "" } },
  "assets": [{ "asset_id": "", "version": "" }],
  "params_version": 0,
  "digest": "sha256:<hex>",
  "disposition": {
    "motion_consumable": false,
    "reason_code": "upstream_unavailable",
    "required": ["public-ai sdk/go motion export", "HUI-2732", "HUI-2733"]
  }
}
```

可空子对象（`context_unavailable_reason`、`brand_config_version`、`published_brand_id`、`published_host`、`short_code`、`authorized_return`）用 `omitempty`：无值就不出现在 JSON 里。

数据来源全部查既有表/既有读取路径：

| 字段 | 来源 |
| --- | --- |
| campaign.* | `campaigns`（`campaignScoped` 已取） |
| store.* | `stores`（`GetStore`，含 0004 加的 `status` 列） |
| brand.brand_id | `tenants.brand_id`（0009） |
| brand.published_brand_id / published_host | `campaign_links` 铸码戳（0009；新增只读 store 函数按 campaign 取，取 `created_at` 最早一条非空戳） |
| brand.context_available / reason / brand_config_version | 复用 `server/internal/brandctx` 既有读取路径 `Client.Read(ctx, host, true)`，host 取该活动链接上已铸的 `published_host`；运行时上游不可用则 `context_available=false` + reason，不伪造 |
| offer.* / cta / channels / aspect_ratios / params_version | `store_motion_requests` 最新行（`LatestStoreMotion`）；无行则空串/空数组/0 |
| landing.short_code | `campaign_links`（最早一条 enabled 短码；无则省略） |
| landing.extra_jump_kinds | `extra_jump_actions` kind 列表，排除 revoked（enabled 不筛选，按票面语义只排除已撤销） |
| landing.authorized_return | `authorized_returns`（未撤销且 href 非空才出现） |
| assets | `campaign_assets`（按 created_at 序） |
| disposition | 常量，恒为上值，本轮永远是 `upstream_unavailable` |

品牌上下文可用性判定（诚实降级，不 fail-closed 报错——brief 是输入投影不是门禁）：

1. `s.Brand == nil` 或 `!s.Cfg.FeatureBrand` → `context_available=false`，`context_unavailable_reason="brand_client_not_configured"`。
2. `tenants.brand_id` 为空 → `false` + `"brand_not_bound"`。
3. 该活动没有任何已铸 `published_host` → `false` + `"no_published_host"`。
4. `s.Brand.Read(ctx, host, true)` 出错或 `Kind != KindReady` → `false` + reason 按 Kind 映射（`unknown_brand`/`brand_suspended`/`brand_retiring`/`domain_error`/`brand_unavailable`）。
5. `KindReady` → `context_available=true`，`brand_config_version=Manifest.ConfigVersion`，`published_brand_id`/`published_host` 取铸码戳值。

digest：对**去掉 `digest` 与 `generated_at` 两个字段**后的固定结构体做 `encoding/json` 序列化（Go 对固定结构体序列化是确定性的），算 sha256，前缀 `sha256:`。排除 `generated_at` 是必须的澄清：它是服务时刻，进 digest 会让「同数据两次相同」不可能成立；裁决中「digest 稳定（同数据两次相同）」与「digest 字段外」以稳定性为准绳，`generated_at` 与 `digest` 同为响应时刻字段，一并排除。`params_version` 变化必然改变 digest 输入，测试钉死。

测试（handler 级，复用 `newFixture`）：访客 401；跨租户 404；无门店 400 `store_required`；digest 稳定（同数据两次 GET digest 相同，`generated_at` 允许不同）；`params_version` 变化 → digest 变化；品牌上游不可用 → `context_available=false` + reason；feature 关（fixture 默认）→ `brand_client_not_configured`；disposition 恒 `upstream_unavailable` 且 `required` 三项逐字；设了 probe 再 GET 计数仍为 0（never 调 probe）；channels/aspect_ratios 空串投影为 `[]`（不是 `null`）。
