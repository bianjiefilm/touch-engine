## 目标

商家在现有商家页创建或恢复一个活动。公共访客在公共活动页明确同意后留资。获客服务按已合入的 HUI-2316 接收这条事实。Touch 只有在 platform-notify 的 deliveries 状态真是 `delivered` 时才把同步写成 `crm_received`。销售工作台若能对同一条 lead 做首次跟进，就在浏览器里做并记下同一个 lead id；做不到就保持「销售工作台首次跟进未完成」，Touch 摘要保持未知，或仅在获客里真有这条线索时显示尚未跟进。

匿名访客不是平台主体，留资不创建平台账号。

## 已合入、本轮不改

- 商家工作台壳、客户卡文案、`salesReceipt`。空活动上「销售已收到 0」是已锁定的空态，不改写成未知，报告里照实记录。
- 待跟进文案。获客摘要失败或未连接时，待跟进保持未知，不写 0，不写成功。
- HUI-1668 活动页轻文案。不把「制作后回到本活动」写成已完成。
- 租户映射。映射只消费 leads-engine `origin/main`（`36774c93`，HUI-2316）。Touch 不重写映射。
- 现有商家后台样式。不引入 shadcn/ui，不整站换肤。

## 发布合同

Touch 出站仍保存 `event_profile` + `payload`，不含联系方式。发给 platform-notify 的正文是包装：

```json
{
  "type": "<event_profile.event_type>",
  "schema_version": 1,
  "app_id": "<scaffold.AppID>",
  "tenant_id": "<event_profile.tenant_scope>",
  "data": { "event_profile": {}, "payload": {} }
}
```

`event_type` 或 `tenant_scope` 为空时，在发 HTTP 之前失败。不发送空的 `idempotency_key` 或零值 `occurred_at`，由 notify 自己派生和填时间。功能开关或配置不齐时，仍在解析之前返回原来的失败。

2xx 响应必须带非空 `event_id`。没有 id 不算已转发，线索停在待同步，不写成 `crm_received`。这个 id 与 submission ref 不是同一个值，写入 `leads_outbox.notify_event_id`（迁移 `0017`）。

确认只查询这个 notify id：`GET /internal/v1/notify/events/{notify_id}/deliveries?app_id=<AppID>`。响应只认 `deliveries`。只含 `items` 的正文不算送达。notify id 为空时跳过确认，保持 `pending_sync`。`delivered` 才是 `crm_received`；`dead` / `subscription_disabled` 才是拒绝。其余继续等待。

`lead.consent_revoked` 仍是本地的临时类型。真实 platform-notify 会拒绝它。撤销的本地归属照旧；报告写明真实撤销投递被拒绝，不把它写成已送达。原归属用获客侧已映射的租户证明：同名新租户不搬走这条线索。

## 跟进摘要

`GET {leads}/internal/v1/campaign-follow-ups` 增加 `source_app=<TOUCH_APP_ID>`。这只是把已合入的消歧参数传过去。401、409、502、超时和 `known:false` 都让待跟进保持未知。lead id 仍只接受 `lead_` 加 32 位十六进制，不放宽。

## 降级

获客或产品图不可用时，活动本身仍能创建、启用并生成链接。客户卡的待跟进写未知，不写 0，不写成功。不启动产品图服务，不接 GoBoost、AiCut 或数字人。

## 浏览器验收

角色是测试用的商家店主、匿名访客，以及获客界面可用时的销售。不是真人满意度。

浏览器只访问各 Web 同源的 `/api/*`。身份登录使用仓库外的本地桩，报告标明是桩。不自己签生产令牌，不手改 SQLite 把 id 拼起来。

窄屏 390×844 留下点击记录和截图，放在 `evidence/hui-1892/`。本轮不改布局，因此不为此重看桌面宽度。退出后重新登录，同一组对象 id 还在。

重放、刷新、切换租户不产生第二条线索。公共页和无权的另一租户管理员看不到 CRM 联系方式。

## 不做

不改 leads-engine、public-ai、GoBoost、AiCut、shuhai-guanlan、product-image-engine、guanlan-order 的源码。不在 leads-engine 里建 worktree。获客从 `origin/main` 的只读副本运行。不杀进程，不占用已在监听的端口。
